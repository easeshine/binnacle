# Kit: how it is built

Row `binnacle`, part of the core · Intent: [authoring](../../../../intents/authoring/intent.md). For a person: `docs/use/keys.md`.

- **A Model tells its watchers in a microtask after a change**, once for the changes made together. A watcher that changes the Model in its own call is told again after that call, never inside it.
- **A Part's Models are watched while the Part is placed.** Each change draws the Part again, as its Handle's `redraw()` does. The watch stops when the Part's Handle is disposed.
- **A named Model is held as a Part is**, in a list by its name, so it goes with its plugin.
- **A theme layer is held as a Part is.** The tokens are laid from the layers, oldest first, at the first read after a layer comes or goes. Then every Part is wrapped again, as its lines can paint with the tokens.
- **A colour token is a Style**: a colour and the attributes `bold`, `dim`, `italic` and `underline`. A colour is one of the sixteen by name, a 256-colour index, or an exact colour, as `#rrggbb`, `okhsl(…)` or `oklch(…)`. A plain colour stands for `{ color }`. `binnacle.theme` refuses a layer with a colour that is not one, and names its Tone.
- **`paint` takes a Style as well as a Tone.** A Style is painted as a Tone's is, for the terminal's colours, and an outer Tone opens again after it ends. A Style's colour that is not one makes `paint` throw, as the theme refuses it. An empty Style gives the text as it is. A Tone stays the way to follow the theme.
- **A List's default row is its pieces.** It is the mark, a space, the box, the label and the description, joined (`list.ts`). The box stays the row's. A row Look of an author's draws instead of all of it, with the default row as its `beneath`. A row wider than the List wraps, as a Part's lines do, so a Request's Choice is read whole.
- **An exact colour is drawn as the nearest of 256** when the terminal does not say in `COLORTERM` that it has truecolor. The colour code is copied from pi-tui.
- **Each attribute is closed by the code that ends it alone**, so a Tone painted inside another leaves the other standing. A Tone also opens again after each close inside its text, a reset or the close of a colour, bold or dim, italic or underline, so the text after an inner Tone or style is drawn in the outer one, as in a heading that holds inline code.
- **A Look is held as a Part is**, in a list by its name, so it goes with its plugin. When a Look comes or goes, or one of its models changes, every Part is wrapped again, as its lines can draw with it. A Look's models are watched while it is held, as a Part's are.
- **The chain of a piece is read at each draw**: the Looks by the instance's name, newest first, then the Looks by the kind's name, newest first, then the component's default. By each name, an author's Looks are above a built-in's, whichever loaded first, as the [Core](../core/AGENTS.md) ranks every registration. A name given twice, as by an instance named like its kind, is read once. `lookOf` calls each `make` as it draws down the chain.
- **The Look beneath is found when it draws, never captured.** Each `beneath` finds its own Look in the chain as it stands, and draws the next one. A `beneath` kept from an earlier draw so follows a Look that unloads, or one that loads beneath later. A `beneath` whose own Look has gone draws the default.
- **A Look set twice by one function has two places in its chain**, as each is held apart, and each goes with its own plugin.
- **A component is made from the author API**, as an author's feature is: a Part in its Place, a Model by its name, its actions, and its Looks read with `lookOf`, down to its default. The Handle that it gives back also takes away its Model's name and its actions.
- **A List sets its mark right as it reads its items**, at a draw or a gesture, and does not tell the Model's watchers, so that a draw does not draw again. When `key()` returns another value, the mark goes to the first item. When the items are fewer than the mark, it goes to the last. With no items there is no mark, and the gestures do nothing.
- **A List's Part has a cursor on its mark**, which the core does not draw, so that the Place scrolls to show the mark. It sets `follow: 'least'`, so the Place keeps the rows it showed, and moves them only as far as the mark needs. It does this with the Focus or without it ([Core](../core/AGENTS.md)).
- **A List's `keysIn` follows Tabs'.** Its actions of the keys are set in the Places `keysIn`, marked `first`, so they come before the Part with the Focus there. They are enabled while the core counts at least one line of the List shown, read with `binnacle.linesShown`, as an author's component can, so a List that draws no line, or that is not on the Screen, leaves the keys to the Part. A click and `toggle` stay in the List's own Place, so a click on the List picks, and moves the Focus there.
- **`fuzzy` ranks by the shortest span**: the fewest characters that an alignment of the query's letters covers in the text, the least over every start. A text that starts with the query comes first, then the shortest span, then the items' order. It does not weigh word boundaries, as dsh's web client does: for names of one word, the span gives the same order in most cases.
- **A List's page is the count of its lines that its Place showed at the last draw**, a wrapped item counted once, and at least one. The core counts them, and the List reads the count with `binnacle.linesShown(name)`, as an author can. A List whose Place is not drawn pages by one item.
- **A box glyph framed in brackets, such as `[x]`, is a frame around what it holds.** Its first and last characters draw in `border`, and a checked box's inside in `success`. A glyph that is not framed draws whole, in `success` when checked and in `border` when not.
- **A List, a Title and Tabs make their text plain**, as it is Untrusted Text.
- **A Line is pi-tui's Input**, copied, one for each value of `key()`, with no prompt of its own: the Look draws the prompt. Its Model is what it holds: when the Model's text of the shown key is not the Input's, a new Input is made from it, with the text pasted so that the cursor is at its end. Only a key that changes the text writes it to the Model, so a `submit` that clears the Model is not undone. The same key calls `change`, after the Model is written, so `change` sees what the person typed and never the author's own changes, which a watch on the Model would also see.
- **A Line's cursor is where its Look draws it.** The Look is handed the text with pi-tui's cursor marker in it, and the core's cursor goes where the marker lands in what the Look draws.
- **Tabs' click is their Part's, not an action**, so that a click on the Tabs moves no Focus, and a Line keeps the keys. A click lands on the tab drawn at the last draw, and a `more` or a separator takes none.
- **Tabs fit from the current tab.** Its neighbours are added after it, then before it, while the row with its separators and its `more` marks fits the width. When the current tab alone does not fit, the marks stay and the tab is cut to the room that is left, with a `more` of its own after it that takes no click, where the `more` fits. A `current()` outside the labels is drawn, and moved from, as the nearest label.

- **`wrap` is the core's wrapping**, the one that wraps a Part's lines, with the prefixes added, so a style that spans a wrap is carried to the next line. The text wraps once, at the width less the wider prefix. A prefix wider than the width draws as wide as it is, and the text gets one cell a line. An empty text gives `first` alone. With `plain`, each of the text's lines is made plain with `toPlainText` apart, as making a text plain takes its line breaks out with the other controls. A line break is `\r\n`, `\r` or `\n`, and each is kept as `\n`.

- **`frame` draws with the theme's `edge`, as a Layout's box does**, its title as the box's title is drawn, cut with the `more` glyph. It reads no `padding`: the lines start at the edge, as in a box of the default padding of 0, and an author who wants room adds it to the lines. Narrower than 4 cells it draws no box, as the box would leave at most one cell for the lines. Its lines are drawn as given, so their styles stay, and a wrap carries a style to the next line, as `wrap` does. Each line's styles are closed at its end, so they do not colour its padding or the edge.
- **`frame` keeps a line's fields, and names no type of the transcript's.** It takes and gives strings, or objects with `text`: each row an object wraps to is the object with that row's `text`, so its `fold` and `run` stay. Its `from` is moved past the left edge on the first row, and each row after it acts from its first cell inside the edge, so a click on the left edge Marks only. A row's `from` bounds only its start, so a click on its padding or its right edge acts as on its text. Narrower than 4 cells, with no edge, the first row keeps its `from` and each row after acts from 0.
- **`rule` is the Title's default row**, moved to the Kit, so a Title and an author's card draw one rule.

- **`markdown` parses with `marked`**, the lexer pi-tui's markdown uses, a dependency of the package, and draws the tokens itself, through a Look for each block, so an author changes one kind of block. It draws no LaTeX, no image and no syntax colours. A token it does not draw, a table, raw HTML, a strikethrough or an image among them, draws as its source text, through `markdown.paragraph`. Each text is made plain before it is drawn, its own line breaks kept, and a soft line break stays a line break, as in pi.
- **A block's Look is given what it draws, already drawn**: inline text with its bold, italic, code and links, and an item's and a quote's blocks drawn at their width less the marker or the `│ `. Blocks are joined by one blank line. A list's items are joined by none, and so are an item's blocks unless its list is loose. A task's box draws as its source at the start of the text, so it counts toward the wrap. An item's marker is `• `, or its number from the list's start and `. `.
- **An unclosed code block draws as code to the end of the text**, as CommonMark reads it, so a streaming answer parsed again at each frame draws its code as code before the fence closes.

- **The package ships the docs, the skill and the source**: `files` holds `docs/`, `skills/` and `src/` beside `dist/`, with no `AGENTS.md`, and `prepack` builds `dist/`, so `pnpm pack` holds what an author reads from a clean checkout.
