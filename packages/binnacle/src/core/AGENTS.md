# Core: how it is built

Row `binnacle`. For a person: `docs/use/index.md`. The Kit's models, theme and Looks are in [`../kit/AGENTS.md`](../kit/AGENTS.md), and the test kit in [`../testing/AGENTS.md`](../testing/AGENTS.md).

- **A feature is a Cordis plugin on the `binnacle` service** ([ADR 1](../../../../adr/0001-a-feature-is-a-cordis-plugin-on-the-binnacle-service.md)). The core is one row, and each feature is a row of its own, which a person turns off in their profile's patch.
- **An author needs only what binnacle exports** ([ADR 4](../../../../adr/0004-an-author-needs-only-what-binnacle-exports.md)). A built-in imports only binnacle's entry, another built-in's entry, cordis, dsh's packages and node's own modules, and a `no-restricted-imports` rule in the root `vite.config.ts` fails `vp lint` on any other import from `src/plugins/`. Each name that a built-in sets or reads, a Place, a Look, an action, a model or a Layout, is in its page under `docs/author/built-ins/`.
- **A Screen is a layout tree of named Places** ([ADR 2](../../../../adr/0002-a-screen-is-a-layout-tree-of-named-places.md)). The Chat's tree is `chat.ts#CHAT_LAYOUT`, frozen, as an author builds on it: the transcript fills, then the Layout `status` that the status line sets, the Layout `request` that the Requests' view sets, and the Layout `composer` that the composer sets take what their lines need. The composer is `unless: 'request'`, so a Request stands in its spot. The Chat's Focus starts in `composer.input`, the composer's Place. `layout.ts#arrange` lays it out; a terminal too small gives up padding, gaps and borders before it cuts rows. A node that takes what its lines need, with less room than that, first shrinks the nodes in it that fill, down to none: the screen is too small only when what does not fill is cut. In a column, the nodes that fill share the rows left by need: each takes no more than its lines need while another needs more, the fewest first, and what is left after is shared evenly. So a Request's short question stays whole above many Choices, and its rule stays.
- **A Layout's tree is grown before each draw** (`tree.ts#grow`). Each `{ layout: name }` node holds the newest Layout set by that name, and each node knows its size. A node with no size fills in a Screen's own Layout, and takes what its lines need in a Layout set by name. A Layout that draws itself, at any depth, draws nothing the second time.
- **A node of `{ most: n }` takes what a node of `'content'` takes, up to `n` cells** (`tree.ts#wantedOf`). Its parent counts it so when it measures what its lines need and when it shares its cells, so a named Layout of `{ most: n }` is at most `n` high. A node of a fixed size counts as its size, and the others as what they need. A node of `{ most: n }` is short of room only when it gets fewer cells than the lesser of `n` and what it needs.
- **Edits apply to a Layout each time it is read for a draw** (`edit.ts#edited`): to the newest Layout set by a Screen's name, or the Screen's own, and to the newest set by a name that a `{ layout: name }` node draws. An anchor is the name in a node's `place` or `layout`. An edit looks for it depth first, through rows, columns, `first`, `over` and `float`, children in order and `over` before `float`, and takes the first node found. It does not look inside a named Layout that the Layout draws. An edit whose anchor is not there does nothing, so it applies again when the anchor comes back.
- **The order of edits never depends on load.** Inserts apply, then moves, then replaces, then removes. Within each kind, a built-in's apply before an author's, as a registration ranks. Then they go by the plugin's own `name`, read from its Cordis fiber, with no name first, then by the edit's JSON text, each compared by code unit. A replace or a remove finds its anchor in the Layout as set, a moved node in its old place, so that of two nodes by one name the first is still the one found. It acts where a move put that node, on what stands in that node's place: of two replaces, the last holds, and a remove after a replace takes out what the replace put. An insert finds its anchor in the Layout as set, then in the nodes that inserts added, in the order they were added. Inserts apply in rounds until a round adds nothing, so an insert beside a node that another insert adds applies whichever sorts first. Inserts beside one anchor keep the order of edits, even when one waited a round for its anchor: after it, the first is next to it, and before it, the last is. An insert is drawn only where its anchor's parent is a row, a column or a `first`. A move takes the node of its first anchor, with its box, out of its place, and puts it beside its second, as an insert of that rank would go. It finds both anchors as an insert does, a moved node in its old place, and does nothing while either is not there, or while the second's parent is not a row, a column or a `first`. What inserts put beside the moved node stays in the old place. A removed root, `over` or `float` draws as an empty column.
- **A separated row draws one line** (`separated.ts#cut`). A row with `separator: true` draws each child at its whole width, with no size and no box, and takes the child's first line: a Part's first line from `lines(width)`, before the core wraps it, or a nested node's first drawn row. A child with no line, or an empty one, takes no divider. The row joins the lines by the theme's `divider` glyph, and cuts the joined line at its width with `more`. Where `more` does not fit, the row draws empty. `gap` does nothing in it. A click lands on the child under it, on its first line, at the column of the Part's lines as drawn at the row's whole width. A nested child takes a click only on its own line, never on a divider or a later child. A click on a divider, or past the cut, lands on nothing. Its width, when its parent measures it, is the joined line's, measured apart, so that measuring leaves no cells to click.
- **A node can take no cells, its box included**: a named Layout or a `first` with no line to draw, and a node hidden by `unless`. Its parent lays out its other children as if it were not there, so no gap is kept for it. A node has a line to draw while a Place in it does. An `unless` that names a Layout it is in finds no lines there, so it always ends.
- **Only a float draws over what it covers** ([ADR 3](../../../../adr/0003-only-a-float-draws-over-what-it-covers.md)). The float is centred across, at the top, the bottom or the centre, and 4 cells narrower than what it covers, at most 80, unless `at.width` says. The layout keeps the cells that a click and the wheel land on, the topmost first: a float's Places, then its whole box, which hits nothing, then what it covers. So a click on a float's border reaches nothing beneath it, and a float inside a float stays on top. A cursor that it covers is not drawn. A float with a line to draw gives its node a line to draw, and its height and width when the node takes what its lines need: the float's width, with its margin, or `at.width`. A node of a fixed size counts as that size when its parent measures what its lines need, so a float holding a `{ fixed: n }` node is as high as `n`, not as what the node holds.
- **`clickFocus: false` holds for each Place inside the node** ([ADR 5](../../../../adr/0005-a-click-takes-the-keys-only-where-a-person-types-or-picks.md)). A click there reaches the Part and its Place's actions, and moves no Focus. A Place that has the Focus keeps it. Each hit that the layout makes keeps whether a click on it moves the Focus, as it keeps whether the mouse reaches it. The Chat's transcript node is `{ place: 'transcript', size: 'fill', clickFocus: false }`.
- **`mouse: false` holds for each Place inside the node.** A click or the wheel on such a Place does nothing, and moves no Focus. It does not go to what is beneath.
- **Edges** are a named table: `theme.ts#edges`. A box's borders are drawn in the theme's `border` Tone, and its default edge, padding and gap are the theme's ([Kit](../kit/AGENTS.md)).
- **A row ends where its style does.** The display clears each row to its end, so the blanks at a row's end are not written while no style is open. The layout follows each style to where it is closed, as a border closes only what it opened.
- **Each registration is held apart**: a Part placed, a Layout, an edit, a Screen shown, a named Model and a theme layer. When a plugin unloads, only its own registrations go, even when another plugin registered the same object, and the newest one left wins again. A plugin that registers while it unloads holds nothing: the call throws Cordis's error, and the screen does not change.
- **A built-in's registration ranks beneath an author's**, whichever loads first, so an author's plugin wins on every start. Among the built-ins, and among the authors, the newest wins. The core reads the registering plugin's fiber, and walks up to the first that has a loader entry, as the loader's `locate` does. A registration is a built-in's when that entry's `name` is the package's or begins with it and `/`: each row of the bundle's patch, and no list kept by hand. The package's name is written once in the source, in `name.ts`, and a test checks it against `package.json` and each of binnacle's rows in `cordis.patch.yml`. A plugin with no entry ranks as an author's. This holds for every registration, an action and a binding too.
- **A Place follows its Part's cursor as the Part's `follow` says.** With `'end'`, the default, the Place shows its end, or the rows the wheel scrolled to, and a cursor outside them is brought to the nearest edge for that draw: below to the bottom row, above to the top row. So the transcript keeps its Marked event's header on the top row. With `'least'`, the rows that a draw shows are kept as the Place's scroll, so the next draw starts from them, and the cursor moves them only as far as its row needs. A `'least'` Place does this with the Focus or without it. So a List keeps its mark in view while the person types in another Place. The terminal's cursor is drawn only at the Part with the Focus.
- **A scroll by an author wins over the cursor until the cursor moves.** The Place with the Focus shows the row of its Part's cursor, however the wheel scrolled it. After `binnacle.scroll(place, pages)`, the Place shows the rows paged to, and the cursor is not drawn while its row is out of view. Once the Part's cursor is at another line or column than when the page was made, as when a key moves it, the Place follows the cursor again. The wheel ends a page, and the Place follows the cursor, as before.
- **The core counts the lines that a Place shows**, a wrapped line once, from the last draw, so that a List's page is as many items as its Place shows. An author reads it with `binnacle.linesShown(place)`, as the List and the offer of commands do.
- **The core tells where the Focus was last moved**, by a person or an author, on the Screen on view, and keeps it after it forgets the move. A Place that stops taking keys loses the Focus at the next draw, and that draw can come before a watcher of the change that hid the Place. So the Requests view knows whether its Line or its Choices had the Focus, and leaves a Focus that a plugin moved. An author reads it with `binnacle.focusMovedLast()`, as the view does.
- **The clock pulls** (`clock.ts#startClock`). A read of `now` notes itself, and starts the timer when it is stopped. A second after the clock last changed, it changes again if `now` was read since then, and else it stops. So a Part that names it is drawn again, reads it again, and keeps it ticking, and once nothing on screen reads it, nothing ticks. A read outside a draw counts as one: a tick too many costs one draw. `now` is read from the time at each read, so a clock that was stopped is never late. The timer is the core's, and stops when the core unloads. `set` on the clock does nothing. The core names it as a built-in, so an author's Model named `clock` ranks above it.
- **The turn follows dsh** (`turn.ts#startTurn`). Its `startedAt` is the time of the session's newest `turn/start`, so a queued turn, which starts while the agent runs, sets it again. Until that event comes, it is when the agent's status became `running`, and it is `undefined` once the status is anything else. When the session opens on an agent that runs, it reads the newest turn that has not ended from the session's events. A stored session has no agent, so no turn. The core names it with `clock`, as a built-in (`models.ts#coreModels`), and `set` on it does nothing.
- **The alternate screen.** binnacle draws on it, and the layout keeps the composer at the bottom.
- **Styled lines.** A Part's lines may carry colour and style. The core takes out every other control sequence. A plugin makes Untrusted Text plain with `view.ts#toPlainText`, and a Part says where its cursor is.
- **Wide content wraps**, as in pi.
- **One owner of the terminal**, `host.ts#Host`, so a crash, a suspend and an unload each give it back once. `capture.ts#capture` holds back what other code writes while binnacle draws.
- **Quitting ends the process.** When binnacle asks dsh to exit, with ctrl+c twice or when the session fails to open, it also asks the process to end 5 seconds later, with the exit code dsh set, by a timer that keeps nothing alive. dsh's `appExit` clears its own forced exit once it has disposed, and a socket left open, such as a proxy's, then holds the process. A process that ends on its own ends at once. 5 seconds is dsh's own grace for disposal, so binnacle never cuts that short.
- **The session.** `session.ts#openChat` opens the Chat's session as dsh's headless bundle does: on `dsh-base`, with no preset, on the default model. A stored session is read once.
- **Hot reload is off** in the bundle's patch, until the core stays up while its plugins reload.
- **pi-tui** is copied, with credit, under `src/terminal/pi/`: its input decoding, text width, editor and input, and how it draws an exact colour.

## Gestures

Row `binnacle`, part of the core. For a person: `docs/use/keys.md`.

- **The Gesture Table** holds pi-tui's editor actions, the `tui.` ids. The copied editor reads its keys from it, but for submit and new line: `tui.input.submit` and `tui.input.newLine` give their keys to the composer's actions `composer.send` and `composer.newline`, and the composer gives the editor no key that they match ([Composer](../plugins/composer/AGENTS.md)). The transcript's up, down and enter are actions too, `transcript.up`, `transcript.down` and `transcript.fold`, that take the keys of `tui.select.up`, `tui.select.down` and `tui.select.confirm` ([Transcript](../plugins/transcript/AGENTS.md)). The composer and the transcript read these keys with `binnacle.keysOf`, as an author can (`gestures.ts#tableKeysOf`).
- **The core's gestures are actions** that the core sets at its start, with no Place, ranked as a built-in's beneath an author's (`actions.ts#coreActions`): `binnacle.clear` (ctrl+c), `binnacle.interrupt` (escape), `binnacle.suspend` (ctrl+z), `binnacle.focus.next` (shift+tab), `binnacle.scroll.up` and `binnacle.scroll.down` (the wheel). So `bind`, `keysOf`, `run` and `beneath()` reach them as they reach an author's. The wheel's scroll reads the cell under the pointer from the core, as an action's `at` is a cell in a Part's lines.
- **`actionsOf`** gives the Gesture Table's actions that match the gesture, then the newest enabled action of each id whose keys match, if it has no Place or acts in the Place with the Focus. An action of another Place is left out, so a list's space does not keep the composer from typing a space.
- **The order a key goes in** (`input.ts#route`):
  1. The actions marked `first` of the Place with the Focus.
  2. The Part with the Focus.
  3. The other actions of the Place with the Focus.
  4. The actions with no Place, the core's among them. `first` puts no action with no Place before the Part.
- **A click goes to the Part under the pointer**, then to the actions of its Place bound to the click's gesture, such as `click` or `shift+click`, with the cell clicked in the Part's lines. A notch of the wheel goes to the actions with no Place. A click below the Part's lines, or on the Place's box, gives an action no cell.
- **The actions of an id are a stack.** The newest enabled one takes the id's gestures, and the others are beneath it. An action that names no `keys`, or no `kind`, keeps those of the action it hides, so a plugin that changes what an action does need not repeat its keys. An action that names no `place` keeps the `place` and the `first` of the action it hides. So an action set by the id of a Place's action takes a gesture only in that Place. An action that names its own `place` acts there. To act from every Place, an author sets an action of a new id.
- **A `place` that is a function** is given the Places that the action would keep with no `place` of its own, as a list, `[]` where the action it hides has none. What it gives is the action's Place, and the action keeps the `first` of the action it hides. The stack is read oldest first, so each function is given what the actions beneath it give. Every read of an action's Place reads it so: a key, a click, `actionsOf`, and the Focus that an action's Place takes.
- **An action that names no `enabled`** is enabled while the newest action it hides that names one is, and always with none. An action that names no `run` runs `beneath()`. Both are read at each gesture and each call, so a gate that unloads beneath an action leaves it enabled.
- **Two actions in one step:** when two enabled actions with different ids take a gesture in one step, the one set last wins. All the actions are held in one list, oldest first, for this.
- **The keys of an action** are its own `keys`, then each binding by its kind, then each binding by its id, oldest first (`actions.ts#Actions`). A binding to a list replaces the keys beneath it, and `[]` unbinds. A binding that is a function is given the keys beneath it, and the core calls it each time it resolves a gesture, so it adds to the keys of an action set after it. Two such bindings by one name both apply, the newest given what the one beneath gives.
- **`beneath()` is found when it runs, never captured**, as a Look's is: the newest enabled action by the id beneath this one, with the same `at`, or nothing. It skips an action whose `enabled()` is false. `binnacle.run(id, at)` and `beneath()` hand on `at` as they are given it, and check `enabled()` and nothing else, neither the Focus nor the Place, as a call is not a gesture. A `beneath()` whose own action has gone does nothing.
- **A Place takes the Focus** while its Part takes keys, or while an action is set that acts in it, by its own `place` or one it keeps, enabled or not, so that the Focus stays while an action is disabled for a moment.
- **The mouse is on by default**, as in pi.
- **The Focus belongs to a Place**, so it stays when the Place's Part is replaced. A Screen names where it starts.
- **A Focus moved waits for its Place.** A click, shift+tab, `binnacle.focus(place)` and a Handle's `focus()` each move it, and the core keeps whether its Place has had it yet. A Place that does not draw yet, or does not take keys yet, takes the Focus once it does. The core forgets the Focus moved only after its Place has had it and stopped taking keys.
- **A scroll by pages** (`drawing.ts#Drawing`) reads where the Place was last drawn: a page is the rows of the Place's box, inside its borders and padding, and it starts from the rows the Place showed, which the cursor of the Part with the Focus can move. The next draw stops it at the first line, as it stops the wheel. A Place that was not drawn, or that has no rows of room, does not scroll, and the Focus does not move. A page of the Place with the Focus wins over its Part's cursor until the cursor moves ([Core](AGENTS.md)).
