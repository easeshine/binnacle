# Composer: how it is built

Row `binnacle-composer` · Intent: [Authoring](../../../../../intents/authoring/intent.md). For a person: `docs/use/composer.md`. For an author: `docs/author/built-ins/composer.md`.

- **The copied editor.** The composer is pi-tui's editor, copied under `src/terminal/pi/components/`, and it stays until a person or an author needs something it cannot do. It keeps the cursor, the history and the paste markers. It draws its cursor only while `composer.input` has the Focus: the Part's `focus` sets the editor's `focused`, and the copy draws its inverse cell only while that is true, so one mark on the screen says where the keys go. It is exported from binnacle's entry as `Editor`, with `EditorTheme` and `CURSOR_MARKER`, and the composer imports it from there, so an author who replaces the composer builds on what it builds on ([ADR 4](../../../../../adr/0004-an-author-needs-only-what-binnacle-exports.md)).
- **The Layout `composer`** is `COMPOSER_LAYOUT`: `{ row: [{ place: 'composer.input', size: 'fill' }], border: ['top', 'bottom'] }`. It is frozen and exported. The Chat draws it with `{ layout: 'composer', size: 'content', unless: 'request' }`. The editor fills `composer.input`, where the Chat's Focus starts. Turned off, the row leaves no composer, as the Layout `composer` is not set.
- **The rules are the Layout's box.** The box draws them in the `border` Tone. So an edit or a Layout of an author's draws them, or none. The copied editor draws no rules.
- **The rows hidden from a tall draft.** While rows of the draft are hidden above it, the editor's first row is `↑ N more`. While rows are hidden below it, its last row is `↓ N more`. The default Look `composer.row` draws these rows in the `muted` Tone, inside the box. They count among the 7 rows shown. A draft that fits draws neither.
- **The draft's rows are the composer's Looks, not the editor's.** The editor draws at the Place's width less the wider of `composer.prefix`'s prefixes, as `wrap` reads them, so an author does no width arithmetic. Then each row goes through `composer.row`, and its prefix is put before it. The cursor's column moves by its row's prefix. The Looks are read at each draw, outside the editor's cache, so the rows follow them when they change.
- **The empty line.** While the draft is empty, `composer.input` draws the first prefix, the editor's cursor, or a blank cell without the Focus, then the Look `composer.empty`, given the cells after the cursor. It is drawn outside the cache of the editor's lines, so that it follows the Look when it changes.
- **The model `composer`**, `{ text, running }`. The editor's `onChange` sets `text` to its expanded text, the paste markers' content in full. When `text` differs from the editor's expanded text, as when an author sets it, the composer calls the editor's `setText`, which drops the markers and puts the cursor at the end. The editor's own changes never differ, so they never call `setText`.
- **Submit and new line are actions** of `composer.input`: `composer.send` takes the keys of the Gesture Table's `tui.input.submit`, enter, and `composer.newline` those of `tui.input.newLine`, shift+enter and ctrl+j, read with `binnacle.keysOf`. The composer gives the editor no key that matches either, so the editor sends nothing and makes no new line by itself.
- **The sequences for shift+enter that name no key**, which pi-tui's editor takes as a new line by its fallbacks, run `composer.newline` while no action other than the editor's is bound to them. So does alt+enter's sequence, which some terminals send for shift+enter. A key bound to both actions runs `composer.newline`, as the editor made a new line before it submitted: ctrl+j's sequence is also enter's. pi's fallback for macOS's Terminal and for Windows reads the shift key through a native helper, and binnacle does not copy it: there, ctrl+j or a backslash before enter is a new line.
- **`composer.send` takes the model's draft first.** It takes the model's draft into the editor, when the two differ. So a draft set in the same call is the one sent, as the offer of commands sets it. Otherwise it sends the draft, trimmed, or steers the turn that runs, adds it to the history, and clears it.
- **The default `composer.send`** keeps the draft while the Chat's session has no agent: a stored session, or one not open yet. With a backslash before the cursor, it takes it out and runs `composer.newline`, wherever `composer.send` is bound. A draft that is only whitespace sends nothing. A command line runs as the next item says.
- **A command line runs in the composer, not in a row.** A draft that starts with `/` and a letter is a command line, when dsh's service `commands` is there. The default `composer.send` gives it, trimmed at its end, to `commands.execute(agent, line, [], signal)`, with the Chat's agent, and waits. While it waits, `running` is `true`, and `composer.send` does nothing. The draft is not changed, and the person can edit it. At `undefined`, the line names no command, and it is sent as a prompt. At an `error` result, or a handler that throws, the draft stays. At a `success`, the line goes into the history. At a prompt or a `success`, the draft is cleared only if it is still the draft that was sent: a draft edited while the command ran stays. The signal aborts when the composer unloads, and dsh then stops waiting for the handler, though the handler can go on. dsh logs the run as `command/run` and `command/done`, and the transcript draws them. With no service `commands`, every draft is a prompt. The row `binnacle-commands` only offers ([Commands](../commands/AGENTS.md)): with it off, a command typed in full still runs.
- **`@deepseek-ai/dsh-commands`** is a peer and a dev dependency, at dsh's pinned version, for the types of its service `commands`, which dsh-base composes.
- **Ctrl+c is the core's `binnacle.clear`.** The composer sets an action by that id in `composer.input`, enabled while the draft has text, which clears it. On an empty draft, the core's takes the key, and quits on a second press within half a second.
- **Esc interrupts**: it is the core's `binnacle.interrupt`; a steer that was queued runs after the interrupt, as in dsh. Ctrl+z suspends.
- **Its other keys come from the Gesture Table**, as the editor reads them there.
- **It passes on each key that another action is bound to.** It takes a key only when `binnacle.gestures.actionsOf` names no action but the editor's `tui.` ones, submit and new line left out. So escape goes on to the core's interrupt, and a key that an author binds to an action with no Place, or to a core gesture, reaches that action.
- **It shows at most 7 rows** of a long draft: the editor is told of 24 rows, and shows 30% of them.
