# Palettes: how it is built

Row `binnacle-palette` · Intent: [Colours](../../../../../intents/palette/intent.md). For a person: `docs/use/colours.md`. For an author: `docs/author/built-ins/palette.md`.

- **The core holds the palette, this row picks it.** The core reads `palette.json`, holds the sources, and draws the palette that `showPalette` or `pickPalette` asks for ([Core](../../core/AGENTS.md)). This row only adds two sources, the command and the List, through the author API. So an author can make another way to pick.
- **The sources** are in `pi.ts`. `pi` gives pi's `dark` and `light`, copied as JSON under `src/terminal/pi/`, with credit in `NOTICE`. The root `vite.config.ts` lets a built-in import them, as data that an author can copy. `pi-themes` lists each `*.json` in `$PI_CODING_AGENT_DIR/themes`, or `~/.pi/agent/themes`, by its file's name, sorted, without reading it, and reads a file only in `load`. A file that is not there rejects with `not there`, and one that is not JSON with `not JSON`.
- **`pi.ts#piLayer` reads a theme as pi reads it.** A theme without each colour that pi's schema asks for throws, and names them (`REQUIRED`). A colour that pi lets a theme leave out takes pi's fallback, as `thinkingMax` takes `thinkingXhigh` (`FALLBACKS`). Each `vars` reference is followed, a loop or a missing var throws, and a colour is `""`, a number, `#…`, `okhsl(…)` or `oklch(…)`. `""` is `{}`. A colour whose name ends in `Bg` is a `background`. The layer gives every Hue: each of the sixteen its own, `orange` 208, so a plugin's Hue beneath does not show through. A var named as a Hue gives it, and `violet` and `purple` give `magenta`, after a var named `magenta`. A Tone takes the var's colour itself, not its Hue, so a person's Hue changes only the Tones that name it.
- **The List `palette.list`** is the Kit's List, in the Layout `palette`, `PALETTE_LAYOUT`, inserted before `composer` with `unless: 'request'`, as the offer of commands is. Its items are the model `palette.picker`'s while it is open: `Terminal`, then each source's, read with `Promise.allSettled` when it opens. A list that comes after the List closed, or opened again, is dropped. The row's own Look `palette.list.row` adds what is wrong, in `error`, and cuts the row with `more`.
- **The mark shows its palette.** A watch of the List's Model runs `showPalette(id)` for each mark a person moves. The mark that the row sets itself, on the palette in use, is noted first, so it shows nothing. A rejection that is an `AbortError`, or that is the file's mistake, which the status line says, is not kept beside the item.
- **A pick gates the List.** Each pick has its number, and esc or a close ends it, so a pick that settles after a newer one began changes nothing. While `picking`, the row's own actions by the List's ids, `palette.list.up` to `palette.list.click`, run nothing, and else run `beneath()`. Esc, `palette.close`, runs `showPalette(undefined)`, which makes a pick that waits reject.
- **The Focus.** `palette.open` focuses `palette.list`, and `palette.close` and a pick that resolves focus `composer.input`. A Request's view takes the Focus, and the Chat's start takes it back when the Request goes, so the row watches `binnacleRequests`, when it is there, and focuses the List again when the last Request goes while the List is open.
- **`/palette`** is registered with dsh's `commands`, when it is there, and runs `palette.open`.
